SERVICE

1. 이 서비스는 무엇인가요?

쌍곰 기술자료봇은 거래처가 요청한 제품 기술자료(MSDS·시험성적서·인증서 등)를 자동으로 이메일로 보내주는 시스템입니다. 영업사원이 일일이 파일을 찾아 첨부할 필요 없이, 웹 화면에서 몇 번의 클릭으로 발송이 끝납니다.

👤 누가 쓰나요?

주로 영업팀이 사용합니다. 거래처에 기술자료를 보낼 때, 그리고 "보낸 게 잘 갔는지" 확인할 때 씁니다.

⚡ 무엇을 하나요?

품목·서류를 선택하고 받는 사람 이메일을 입력하면 → 자동으로 ZIP 파일을 만들어 메일 발송합니다. (최대 3명 동시 발송)

💰 비용은?

사용 중인 모든 외부 서비스가 무료 플랜입니다. 현재 사용량 기준으로 추가 비용이 들지 않습니다.

💡 핵심 한 줄: "카카오톡 채널 → 웹 요청 화면 → 자동으로 자료 ZIP 생성 → 이메일 발송" 이 전부입니다. 나머지는 전부 자동으로 돌아갑니다.

HOW IT WORKS

4. 요청부터 수신까지 — 동작 흐름

영업사원이 "발송 요청"을 누르면 내부에서 이런 순서로 일이 일어납니다.

  1. 요청 입력 — 영업사원이 /request 화면에서 품목/서류 선택 + 받는 사람 이메일(최대 3명) 입력
  2. 이메일 검증 — 입력한 이메일 도메인이 실제 존재하는지 자동 확인(오타·없는 주소 차단)
  3. 접수 & "처리중" 기록 — 서버가 요청을 받고, 발송 기록에 "처리중"으로 즉시 남김
  4. 자료 묶기(ZIP) — GitHub에 캐시된 기술자료 PDF들을 모아 ZIP 파일 1개로 생성
  5. Supabase 업로드 — 만든 ZIP을 Supabase 창고에 올리고, 다운로드 링크 생성
  6. 이메일 발송 — Gmail로 받는 사람에게 다운로드 버튼이 담긴 메일 발송(받는 사람 수만큼)
  7. 기록 완료 — 발송 기록을 "발송 완료"로 갱신. 일부 누락 시 "부분"으로 표시 + 관리자에게 경고 메일
  8. 24시간 후 자동 정리 — 6시간마다 도는 청소 작업이 24시간 지난 ZIP을 자동 삭제(창고 비움)
✅ 영업사원이 하는 건 1번뿐입니다. 2~8번은 전부 자동입니다.

8. 문제 해결 (증상별)

자주 생길 수 있는 증상과 원인·해결을 정리했습니다.

📭메일이 안 왔어요
원인 처리에 30초~1분 걸림 / 스팸함 분류 / 이메일 오타
해결 1분 기다린 뒤 스팸함도 확인 → /status에서 그 이메일 조회해 "발송 완료"인지 확인 → 필요시 재전송
🚫메일이 스팸함으로 가요
원인 개인 Gmail 발송 + 다운로드 링크 특성상 일부 수신자가 스팸 처리(수신자마다 다름)
해결 받는 분께 "스팸 아님" 처리 + 주소록 추가 요청 → 다음부터 정상. 근본 해결은 회사 도메인 발송 전환
⏳다운로드 링크가 만료됐대요
원인 링크는 발송 후 24시간만 유효(보안·용량 관리)
해결 /status에서 해당 발송 찾아 재전송 → 새 링크가 발송됨
📂"부분" 상태가 떴어요
원인 요청한 서류 중 일부 원본이 깨져 ZIP에서 빠짐(메일은 갔지만 자료 일부 누락)
해결 /admin/docs-health에서 어떤 서류인지 확인 → 홈페이지 원본 복구. 정상 신호이니 끄지 마세요
🐢웹페이지가 처음에 느려요
원인 Render 무료 서버가 잠깐 잠들었다 깨어나는 "콜드 스타트"(~50초)
해결 잠시 기다리면 정상. UptimeRobot이 5분마다 깨우지만 가끔 발생할 수 있음
😴Supabase가 멈췄어요(일시정지)
원인 무료 플랜은 7일 미사용 시 일시정지. 보통 6시간마다 핑으로 방지됨
해결 Supabase 대시보드에서 프로젝트 "Restore"(복구) 클릭 → 다시 동작
🔑관리자 페이지가 "unauthorized"래요
원인 주소 뒤 ?token= 값이 틀렸거나 빠짐
해결 아래 핵심 정보의 정확한 토큰을 주소에 붙여 접속

11. 수정·개선이 필요할 때

이 서비스는 바이브코딩(Claude Code와 대화하며 만드는 방식)으로 제작됐습니다. 수정도 같은 방식으로 합니다.

  1. 무엇을 바꾸고 싶은지 Claude Code에게 말합니다 — "발송 완료 화면 색을 바꿔줘" 처럼 자연어로
  2. Claude가 코드를 수정하고 GitHub에 올립니다(git push)
  3. Render가 자동으로 감지해 재배포합니다 — 보통 2~3분 후 실제 화면에 반영
  4. 새로고침해서 확인 — 캐시 때문이면 Ctrl+F5
💡 코드는 전부 GitHub 저장소 한 곳에 있습니다(github.com/kwhssangkom-collab/ssangkom-chatbot). 핵심 파일은 app.py 하나입니다.
🔒 수정할 때도 비밀키는 절대 코드에 넣지 않습니다. 새 비밀이 필요하면 Render 환경변수에 추가하세요.

GLOSSARY

13. 용어집 (쉽게 풀이)

배포(Deploy)

수정한 코드를 실제 서비스에 반영하는 것. 여기선 GitHub에 올리면 Render가 자동으로 해줍니다.

서버 / 호스팅

웹페이지를 24시간 띄워두고 요청을 처리하는 컴퓨터(클라우드). 여기선 Render가 담당.

환경변수

코드에 직접 안 적고 따로 보관하는 설정값(비밀키 등). Render 설정에서 관리.

토큰(Token)

관리자 페이지를 여는 비밀 암호. 주소 뒤 ?token= 으로 붙입니다.

캐시(Cache)

자주 쓰는 자료를 빠르게 쓰려고 복사해 둔 것. 여기선 기술자료 PDF를 GitHub에 복사.

콜드 스타트

잠든 무료 서버가 다시 깨어나는 데 걸리는 시간(~50초). 첫 접속이 느린 이유.

ZIP

여러 파일을 하나로 묶은 압축 파일. 기술자료 여러 개를 한 번에 보내려고 사용.

RLS / 버킷 잠금

Supabase 저장소의 보안 규칙. 외부인이 파일을 열람·삭제 못 하게 막아둔 설정.

FAQ

14. 자주 묻는 질문

내 PC를 꺼도 서비스가 돌아가나요?
네. 모든 게 클라우드(Render·Supabase·GitHub·Gmail)에서 돌아갑니다. PC는 코드를 수정해 올릴 때만 필요합니다.
한 번에 몇 명에게 보낼 수 있나요?
요청 화면에서 "+ 수신 이메일 추가"로 최대 3명까지 동시 발송할 수 있습니다.
"부분"은 실패인가요?
아닙니다. 메일은 정상 발송됐지만 자료 일부가 누락된 상태입니다. 원본이 깨진 서류 때문이며, 서류 점검 페이지에서 확인할 수 있습니다.
관리자 토큰을 바꾸고 싶어요
Render 대시보드 → 서비스 → Environment → ADMIN_TOKEN 값을 새 문자열로 변경 후 저장하면 됩니다. (이 가이드북의 토큰 값도 같이 갱신하세요)
발송 기록은 얼마나 보관되나요?
기록(누가·언제·무엇을 보냈는지)은 Supabase에 계속 보관됩니다. 단, 실제 ZIP 파일은 24시간 후 삭제됩니다(다운로드 링크 만료).
기능을 추가하려면 개발을 배워야 하나요?
아니요. Claude Code에게 원하는 것을 말로 설명하면 코드 수정·배포까지 진행됩니다. 다만 큰 변경은 검토가 필요하니 천천히 진행하세요.
이 가이드북을 영업팀에 공유해도 되나요?
관리자 토큰이 포함된 12번 핵심 정보·9번 보안 부분은 제외하고 공유하세요. 영업사원에게는 요청/발송확인 화면 사용법만 안내하면 충분합니다.

이 문서는 서비스 구조 이해·운영·문제해결을 돕기 위해 작성되었습니다. 시스템이 바뀌면 이 문서도 함께 갱신하세요.
